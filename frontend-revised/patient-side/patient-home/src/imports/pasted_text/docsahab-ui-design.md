IMPORTANT INSTRUCTIONS

This task is strictly about FRONTEND UI/UX DESIGN.

Do NOT design:

Backend systems
APIs
Databases
Technical architecture
System integrations
GPS implementation
Notification infrastructure
Engineering workflows

Assume all backend functionality already exists.

Focus ONLY on:

Mobile UI design
Visual hierarchy
User experience
Layout
Typography
Emergency usability
Information architecture
Touch targets
Emotional design

Create realistic production-ready mobile app screens.

==================================================

PROJECT

Design a high-fidelity mobile application UI for Docsahab.

Docsahab is a healthcare emergency coordination platform designed to improve survival outcomes during medical emergencies by reducing delays and information gaps between patients, ambulances, and hospitals.

This is NOT:

A fitness app
A health tracking app
A navigation app
A hospital dashboard
A cyber-tech startup interface

This IS:
A calm, trustworthy emergency medical assistance platform.

==================================================

PATIENT DESIGN PHILOSOPHY

The patient is the least trained user in the ecosystem.

The patient may be:

Scared
Injured
In pain
Panicking
Helping a loved one
Helping an unconscious person
Experiencing a medical emergency

The design must reduce thinking.

One screen.
One decision.

The user should instantly know what to do.

==================================================

VISUAL DESIGN SYSTEM

Create a premium healthcare experience.

Use:

White backgrounds
Soft medical blue
Light gray surfaces
Subtle green success states
Soft amber warning states
Soft red only when absolutely necessary
Rounded modern UI
Large typography
Large touch targets
Plenty of breathing space

Avoid:

Dark mode
Cyberpunk aesthetics
Hacker-style interfaces
Military command center styling
Neon colors
Excessive gradients
Futuristic dashboards
Startup template aesthetics
Generic AI-generated card layouts

The design should feel:

Human
Warm
Trustworthy
Reassuring
Professional
Calm

The interface should feel like a real healthcare product used by actual people.

==================================================

SOS BUTTON DESIGN REQUIREMENTS

The SOS button is the most important action.

However:

Do NOT create:

Giant flashing red buttons
Panic-inducing visuals
Disaster-alert aesthetics
Overly aggressive emergency styling

The SOS action should be:

Clearly visible
Easy to locate
Easy to tap
Calm but urgent
Professional
Trustworthy

Use hierarchy and spacing to make it stand out.

Not fear.

The user should feel:

"Professional help is one tap away."

NOT

"Something terrible is happening."

==================================================

CREATE THREE MOBILE SCREENS

==================================================
SCREEN 1

HOME SCREEN

Purpose:
Emergency readiness.

This should be the simplest screen in the application.

TOP SECTION

Docsahab branding
Friendly healthcare message

Example:

Emergency Medical Assistance

PRIMARY FOCAL AREA

Large SOS action.

Most visually important element on screen.

Clean.
Modern.
Healthcare-oriented.

SECONDARY ACTIONS

Medical Profile

Emergency Contacts

Emergency Guide

These should remain clearly secondary to SOS.

DESIGN GOAL

When someone opens this screen they should immediately understand:

"If I need emergency help, I press here."

==================================================
SCREEN 2

SOS ACTIVATED

Purpose:
Reduce panic and create reassurance.

The moment SOS is activated, the entire experience changes.

PRIMARY MESSAGE

Large reassuring status message.

Example:

HELP IS ON THE WAY

This should be the first thing users notice.

AMBULANCE STATUS

Show:

Ambulance Assigned

ETA

Hospital Selected

EMERGENCY PROGRESS

Simple visual tracker.

Example:

✓ SOS Sent

✓ Ambulance Assigned

→ Ambulance En Route

○ Ambulance Arrived

○ Patient Picked Up

This should create confidence and reduce uncertainty.

ACTIONS

Call Ambulance

Share Status

Family Updates

DESIGN GOAL

The user should feel:

"The system is handling this."

==================================================
SCREEN 3

MEDICAL PROFILE

Purpose:
Store information that may save time during treatment.

PROFILE INFORMATION

Name

Age

Blood Group

Allergies

Chronic Conditions

Current Medications

EMERGENCY CONTACTS

Emergency Contact 1

Emergency Contact 2

Emergency Contact 3

DESIGN GOAL

Simple.
Clear.
Easy to maintain.

==================================================

UX REQUIREMENTS

No dashboards.

No analytics.

No graphs.

No health scores.

No fitness tracking.

No AI symptom checker.

No unnecessary features.

No information overload.

Large typography.

Large touch targets.

Maximum readability.

Minimal cognitive load.

==================================================

PRIORITY ORDER

SOS
Help Is On The Way
Ambulance ETA
Hospital Status
Medical Profile
Emergency Contacts
Emergency Guide

==================================================

FINAL GOAL

Create a patient experience that feels calm, trustworthy, and human.

Before SOS:
"I know where to get help."

After SOS:
"Help is coming."

The design should feel like a real healthcare product used during real emergencies, not an AI-generated startup mockup.
